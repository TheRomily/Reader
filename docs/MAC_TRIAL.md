## 在自己的 Mac 上运行

1. 将完整 Reader 源码放到 Mac 的本地文件夹。若使用本次交付的源码 ZIP，解压后进入其中的 `Reader` 文件夹；该包不包含书库、账号或签名证书。
2. 安装 Node.js 24 LTS。首次使用 Mac 构建工具时，在终端运行 `xcode-select --install`，按系统提示完成 Command Line Tools 安装。
3. 在本地终端进入项目目录并运行：

```bash
npm ci
npm run mac:check
npm run mac:trial
```

首次安装和构建需要网络下载 npm 包与经过校验的 Electron 发行文件。脚本只在 macOS 上执行，按本机 Node.js 的架构生成 Apple Silicon / Intel 版本；无需把证书或密码发到聊天中。

`mac:trial` 依次执行：

1. 检查 Mac 打包与签名工具。
2. 运行现有解析与签名配置测试、构建生产界面。
3. 使用明确的 `identity: "-"` 生成本机 ad-hoc 签名的 `.app`，并禁止因没有开发者证书而静默跳过签名。
4. 使用 `codesign --verify --deep --strict` 验证签名，并核对可执行文件架构。
5. 创建包含「阅境.app」和 Applications 快捷入口的 DMG。
6. 只读挂载 DMG，再次校验其中的应用。
7. 从 DMG 内启动应用，以独立临时书库验证 PDF、EPUB、MOBI、翻页、进度与书签恢复、渲染进程隔离以及转换 IPC。转换 IPC 使用测试程序，仅验证调用链，实际 Calibre 转换不因此被判定通过。
8. 关闭仅由验收启动的应用，卸载测试磁盘映像，保存本次结果与 DMG 的 SHA-256。

不会读写或清理你日常使用的书库；若检测到临时数据目录隔离失败，测试会停止。

打开 DMG，将「阅境」拖入 Applications。若已有同名应用，请先保留旧版本，再决定是否替换。本机生成的试用包不属于已公证分发包；若系统阻止启动，请使用系统「隐私与安全性」中针对该应用的授权入口。不要关闭全局安全检查。

## 仍需手动完成的实机检查

将以下结果记录到本次验收记录；未检查的项目应记为「未测」，不要记为通过。

- 从 Applications 启动；窗口缩放、最大化、全屏及退出正常。
- 分别导入自己的 PDF、EPUB、MOBI/AZW3 与漫画压缩包，检查插图、章节、中文字体和实际翻页效果。
- 单页、双页、连续阅读与日漫方向符合预期；Retina 屏幕下画面与文字清晰。
- 在长章节中滚动后退出，再次启动确认进度、书签和笔记保留。
- 验证本机中文系统语音能实际发声；没有安装中文语音时，先在系统设置中安装。
- 若安装 Calibre，用真实文件转换并回读输出；未安装时将此项记为「未测」。

正式分发给其他用户仍需 Developer ID 签名与 Apple 公证，不能用本机 ad-hoc 签名代替。Windows 的实机验收与 Authenticode 签名是另一条流程，本次 Mac 试用不覆盖它们。
